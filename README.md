# daylo-web

Landing page for [Daylo](https://github.com/henfrydls/daylo), a simple habit tracker that keeps your data on your device. Live at [daylo.henfrydls.com](https://daylo.henfrydls.com/).

## What's in the page

- The year at a glance: an example heatmap that adapts to the screen width
- Download button that picks the visitor's system, with every platform one click away
- Live demo of the app at `/demo/`, built from the same code as the installers
- Privacy policy at `/privacy/`
- Light, fast, no framework: one HTML file, one stylesheet, a few kilobytes of script

## Structure

```
site/                 Document root, served as-is
  index.html          Landing page
  privacy/index.html  Privacy policy
  assets/             Screenshots, social image, icons
  demo/               Web build of the app (generated by deploy/build.sh)
deploy/
  config.env          Domain, paths, Umami site id
  build.sh            Refresh site/demo and the version from the latest release
  server-setup.sh     One-time server setup: clone, nginx site, certificate
  pull.sh             Publish the latest main on the server
  nginx/              nginx site configuration
```

## Updating after a Daylo release

```bash
deploy/build.sh
```

This downloads the `daylo-web-demo` artifact of the release's workflow run, checks that the build contains no analytics, adds the demo notice and this site's Umami script to it, writes it to `site/demo/`, and updates the version in the landing page. Commit the result and open a pull request. Once merged, on the server:

```bash
sudo /opt/daylo-web/deploy/pull.sh
```

## Analytics

The site uses a self-hosted [Umami](https://umami.is) instance: no cookies, no IP addresses, no cross-site tracking. The app itself sends nothing. See the [privacy policy](https://daylo.henfrydls.com/privacy/).
